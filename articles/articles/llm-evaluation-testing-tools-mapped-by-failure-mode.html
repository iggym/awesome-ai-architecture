LLM Evaluation & Testing Tools, Mapped by Failure Mode

A curated reference for engineers comparing evaluation and testing tooling — organized by the failure mode each tool actually addresses, not by marketing category.

Exclusion Criteria — Read First

This list deliberately excludes three categories of tools that frequently appear in "LLM testing" roundups. First, pure observability platforms without an evaluation primitive — if you can only view traces but cannot score them against a dataset, you have a dashboard, not a test. Second, thin wrappers around openai.ChatCompletion that add a "run this prompt five times" button; that is invocation with extra steps, not testing. Third, academic benchmark mirrors with a pricing page — a Hugging Face leaderboard repackaged as a product does not catch regressions in your specific retrieval pipeline. We also exclude eval features bolted onto general-purpose MLOps platforms where the LLM-specific surface area was still in beta as of November 2024; a roadmap slide is not a test runner. The bar for inclusion is the one we'd apply to a unit-testing framework: define a test, run it against your own data, fail loudly on regression. If it cannot do all three, it is not on this list.

Silent Prompt Regressions on the Long Tail

The first failure mode is the regression you didn't ship on purpose: a one-line edit to a system prompt improves the median case and quietly breaks the 5th percentile. Evaluating this by hand-eyeballing the top three outputs is how regressions ship on Fridays.

Silent Prompt Regressions

Promptfoo

Runs YAML-defined eval matrices locally or in CI; fits teams that want a failing test to block a merge rather than arrive as a Slack notification after the fact.

Silent Prompt Regressions

Gentrace

Diffs LLM pipeline outputs against a pinned golden set before deploy; fits teams whose deploy is already gated by traditional CI and want eval results in the same gate, not a separate dashboard.

RAG Retrieval Failures Hidden by Confident Prose

RAG evaluation is its own failure mode because a wrong answer can look right and a right answer can be ungrounded. A retrieval step that surfaces the wrong chunk still produces fluent text — the gap between "sounds correct" and "is correct" is where production RAG silently rots.

RAG Retrieval Failures

RAGAS

Faithfulness, context relevance, and answer relevance metrics computed without reference answers; fits teams that cannot afford to label golden outputs for every query.

RAG Retrieval Failures

TruLens

The RAG triad of context relevance, groundedness, and answer relevance instrumented directly into app traces; fits teams that want the diagnosis attached to the trace, not filed in a separate report.

LLM-as-Judge Reliability Doubts

Once you delegate grading to another LLM, the new question is whether the judge is itself calibrated. A judge that always returns "yes, this is good" is not a test — it is a rubber stamp with API costs.

LLM-as-Judge Reliability

DeepEval

14+ metrics with documented human-correlation scores and pytest-style assertions; fits teams that want to argue about which metric to use, not whether metrics are reliable.

LLM-as-Judge Reliability

Patronus AI

Production evaluators benchmarked against regulatory datasets like FinanceBench; fits regulated-industry teams that need to defend the eval in front of an auditor, not just a teammate.

Agent Trajectories as Black Boxes

Agent failures are not point failures — they are paths. A single wrong tool call three steps in produces a final answer that looks defensible until you trace the route that got there, and most evaluation tooling stops at the final token.

Agent Trajectory Black Boxes

Inspect AI

Solver-and-scorer architecture with full trace replay; fits teams evaluating agentic models where the trajectory, not just the answer, is the artifact under test.

Agent Trajectory Black Boxes

Phoenix (Arize)

OpenTelemetry-native LLM traces with span-level eval annotations; fits teams already invested in OTel that want evaluation layered onto existing instrumentation rather than bolted on as a parallel pipeline.

Evals That Aren't Reproducible Across the Team

An eval that only runs on one developer's laptop is an anecdote. The fifth failure mode is the dataset that drifts, the prompt that isn't pinned, the scoring run that no one can reproduce three weeks later — the social failure, not the technical one.

Eval Reproducibility

LangSmith

Datasets, evaluators, and experiment runs versioned and shareable inside the LangChain ecosystem; fits teams already committed to LangChain who want eval to live where their orchestration does.

Eval Reproducibility

Braintrust

Git-like dataset and eval versioning with a CLI that drops into existing CI; fits teams that treat the eval as a first-class artifact alongside code and want the diffs to look familiar.

Bold Reframe

Most "LLM evaluation" tools are observability dashboards wearing a testing costume — this list keeps only the ones that can fail a build.

What's Still Missing (as of Nov 2024)

A shared, language-agnostic spec for eval datasets — every tool above ships its own JSONL dialect, and portability between them is hand-rolled. The category also lacks a credible answer for evaluating long-horizon agents beyond a handful of turns; most judge-based metrics were validated on single-shot Q&A and quietly degrade on multi-step trajectories. Until those gaps close, "LLM testing" is still more improvisation than engineering.
